# Curation Score Analysis Report

## 1. Executive Summary

### Experiment Objective
The objective of this experiment was to safely test lowering the curated product offers expansion threshold (`EXPAND_MIN_SCORE`) from the baseline value of `0.86` to a target test value of `0.80`. The purpose was to evaluate whether a lower threshold would match and link more candidate offers to curated products without introducing quality regressions or mismatch errors.

### Test Setup
- **Baseline Database (baseline.db)**: Run with `EXPAND_MIN_SCORE=0.86`.
- **Target Test Database (test.db)**: Run with `EXPAND_MIN_SCORE=0.80`.

### Key Findings
There is **absolute parity** (0 differences) between `baseline.db` (0.86) and `test.db` (0.80) in both product counts and offer mappings:
- **Product Count**: Both databases produced exactly **206 products**.
- **Matched Offers**: Both databases produced exactly **588 matched offers**.

### Technical Explanation
This absolute parity occurs due to the implementation details of the scoring function `scoreCandidate` in `scripts/expand-curated-product-offers.ts`. The function returns only discrete, step-like scores rather than continuous fractional scores:
1. **`1.0`**: Returned when there is an exact match on `modelKey` (`offer.modelKey === product.modelKey`).
2. **`0.94`**: Returned when all model tokens match and there are 2 or more distinctive model tokens (`coverage === 1 && productTokens.length >= 2`).
3. **`0.90`**: Returned for the `Papelillos` category when the candidate has the same paper variant and compatible size (`product.category === "Papelillos" && hasMatchingPaperTips(product, offer)`).
4. **`null`**: Returned in all other cases.

Because there are no possible score values calculated between `0.80` and `0.86` (all valid matches score $\ge 0.90$, and non-matches return `null` which is filtered out), lowering the threshold to `0.80` has no effect on the candidate selection.

## 4. Final Recommendations

Based on the findings of this experiment, the following recommendations are proposed:

1. **Lowering the Threshold (EXPAND_MIN_SCORE=0.80)**:
   - Lowering the threshold to `0.80` is functionally **safe** (it does not introduce any new false positives because the output is identical to `0.86`).
   - However, it is **redundant** and has no real-world impact due to the discrete nature of the current scoring function.

2. **Upgrading the Scoring Logic**:
   - To safely expand match coverage in the future, the `scoreCandidate` function should be refactored to return **fractional/continuous scores** (e.g., calculated using token coverage ratios like Jaccard similarity or Dice's coefficient over descriptive terms).
   - This should be combined with **strict validation guardrails** implemented as hard rules. Candidates must be discarded if they fail validation, regardless of their text similarity score.

3. **Stricter Validation Constraints to Avoid False Positives**:
   - **Unit/Pack Validation**: Ensure quantity matches (e.g., detecting `1u`, `3u`, `3-pack`, `x3`) match exactly.
   - **Variant Validation**: Strictly separate special editions or colorways (e.g., `Onyx`, `Gold`, `Classic`) for premium items like vaporizers.
   - **Format Validation**: Distinguish paper booklets from paper rolls/spools, and standard packs from kits (e.g. `Deluxe Kit`, `Connoisseur`).
   - **Grinder Part Check**: Explicitly match the number of parts (e.g., `2-partes`, `3-partes`, `4-partes`).
   - **Angle Fitment Check**: Verify compatibility of angles (e.g., `45°` vs `90°`) for bangers/diffusers.
